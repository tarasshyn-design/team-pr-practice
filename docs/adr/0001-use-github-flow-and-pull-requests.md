# 0001. Використання GitHub Flow та Pull Request із Code Review

- **Статус:** Прийнято
- **Дата:** 2026-11-27
- **Учасники:** Команда проєкту `team-pr-practice`

## Контекст
Над репозиторієм `team-pr-practice` працюють кілька учасників. Прямі зміни в гілку `main` без перевірки підвищують ризик конфліктів, помилок та неузгодженості коду і документації.

## Рішення
Ми використовуємо модель **GitHub Flow**:
- Усі нові зміни та виправлення робляться в окремих гілках (`feature/...`, `fix/...`).
- Злиття у `main` відбувається лише через **Pull Request** після попереднього **Code Review**.
- Коміти робляться атомарно з чіткими повідомленнями.

## Наслідки
- **Плюси:** вища якість коду й документації, прозора історія змін, менше конфліктів у `main`.
- **Мінуси:** злиття змін займає трохи більше часу через етап рев'ю.
