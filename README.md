# team-pr-practice

Навчальний репозиторій для практичної роботи № 5 з командної розробки за моделлю **GitHub Flow**, оформлення **Pull Request** та проведення **Code Review**.

## Правила роботи
- Основна гілка `main` захищена й оновлюється лише через Pull Request після рецензії партнера.
- Гілки створюються під конкретну задачу з дошки (наприклад, `feature/...` або `fix/...`).
- Коміти робляться атомарно з повідомленнями в наказовому способі (наприклад, `Add ...`, `Update ...`).

# team-pr-practice

Навчальний репозиторій для практичних робіт із курсу «Основи програмної інженерії та конструювання програмного забезпечення». Демонструє командну роботу за моделлю GitHub Flow, оформлення Pull Request, проведення Code Review та базову валідацію даних у JavaScript.

## Можливості

- Робота в команді за моделлю GitHub Flow (окремі гілки `feature/...` / `fix/...`, Pull Request та Code Review перед злиттям у `main`).
- Атомарні коміти з чіткими повідомленнями у наказовому способі.
- Валідація даних у модулі `validator.js` (зокрема перевірка email).
- Ведення документації та журналу архітектурних рішень (`docs/adr/`).

## Встановлення / запуск

1. Клонуйте репозиторій та перейдіть у теку проєкту:

`git clone https://github.com/tarasshyn-design/team-pr-practice.git && cd team-pr-practice`

2. Створіть робочу гілку від актуальної `main` (за правилами роботи в репозиторії):

`git checkout main && git pull && git checkout -b feature/update-readme`

3. Запустіть проєкт або перевірку скриптів (за наявності Node.js / залежностей у проєкті):

`node -v`

## Приклад використання

Приклад перевірки модуля валідації (`validator.js`) у середовищі Node.js:

`node -e "const validator = require('./validator'); console.log(validator);"`

Після внесення змін у код або документацію створити коміт, запушити гілку та відкрити Pull Request на перевірку учасником команди.

## Структура проєкту

- `docs/adr/` — журнал архітектурних рішень (`ADR-0001`, `ADR-0002` тощо).
- `validator.js` — модуль функцій валідації (зокрема перевірки email).
- `README.md` — опис проєкту, правила роботи, запуск та структура.

## Як зробити внесок

1. Створіть окрему гілку (`feature/...` або `fix/...`) від `main`.
2. Зробіть атомарні коміти з повідомленнями в наказовому способі (`Add ...`, `Update ...`).
3. Відкрийте **Pull Request** у `main` і пройдіть **Code Review** (особливо якщо гілка `main` захищена від прямих пушів).
